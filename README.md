# FunPayAPI

<img width="1376" height="768" alt="FunPayAPI" src="https://github.com/user-attachments/assets/e4beb286-aab1-4ce2-88ac-c73a360d1b35" />

> Неофициальная асинхронная библиотека для работы с FunPay.Проект пока в разработке. В прод лучше не тащить.

FunPayAPI написана на Rust. Основная идея простая: дать удобную основу для асинхронных проектов, не заставляя держать весь код в одном огромном файле.

## Что есть

| Фича | Что это значит |
| --- | --- |
| Асинхронность | Можно нормально работать с несколькими задачами сразу, не блокируя приложение на каждом запросе. |
| Rust | Быстро, строго по типам и без лишнего расхода ресурсов. |
| Роутеры | Логику можно разносить по модулям, а не превращать проект в один большой файл. |
| Профиль запросов | Запросы стараются выглядеть так, будто их отправляет обычное пользовательское устройство. Это ничего не гарантирует и не отменяет правила площадки. |

## Важно

Библиотека **неофициальная**. Она никак не связана с FunPay и не является продуктом платформы. Используешь — используешь на свой страх и риск.

API ещё может меняться, что-то может ломаться между обновлениями, а документации может не хватать. Если тебе нужна стабильная библиотека для серьёзного проекта, лучше пока подождать. Если хочется попробовать, потестировать или помочь с разработкой — добро пожаловать.

## Статус

Сейчас проект находится в активной разработке. Многое уже может работать, но считать библиотеку готовой пока рано.

| Пункт | Статус |
| --- | --- |
| Разработка | Идёт |
| Готовность для прода | Пока нет |
| Стабильность API | Не гарантируется |
| Ломающие изменения | Возможны |

## Хочешь помочь?

Форкай репозиторий, делай изменения и открывай pull request. Подойдут исправления, новые возможности, тесты, примеры и правки документации.

Не заливай в репозиторий токены, cookie, пароли и другие секреты. Если нашёл проблему или хочешь что-то обсудить, сначала лучше создать issue с понятным описанием.

## Использование

Примеры и нормальная документация будут добавляться по мере разработки. Пока лучше смотреть актуальный код проекта и тестировать всё на отдельном аккаунте.
